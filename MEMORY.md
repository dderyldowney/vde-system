## SSH Test Isolation Pattern

```python
# before_scenario: backup ~/.ssh/vde/ for SSH-touching scenarios
if any(t in scenario.effective_tags for t in ('requires-docker-ssh', 'requires-ssh-agent')):
    context._vde_ssh_backup = _backup_vde_ssh_dir()
# after_scenario: restore unconditionally
_restore_vde_ssh_dir(getattr(context, '_vde_ssh_backup', None))
```

Also clean public-ssh-keys/ of non-`vde_*` test files in after_scenario.

## Context Bleed Gotcha

Behave reuses the same context object across scenarios in a feature. Any flag set in a step
(e.g. `context._unset_ssh_auth_sock = True`) persists into the next scenario unless reset in
`before_scenario`. Always reset custom flags in `before_scenario`.

## vm-types.json Isolation

`data/vm-types.json` is the primary source of truth (not vm-types.conf). Tests that write
to it (e.g., "Set display name" step adds vde-displaytest) can bleed into critical-path checks if
not cleaned up. The configs/ backup in environment.py now ALSO snapshots vm-types.json:

```python
vm_types_json = Path(VDE_ROOT) / 'data' / 'vm-types.json'
shutil.copy2(str(vm_types_json), os.path.join(tmpdir, 'vm-types.json'))
```

Triggered for @user-guide-internal and @user-guide-installation features.
If stale vde-displaytest appears: `python3 -c "import json; p='data/vm-types.json'; d=json.load(open(p)); d['vms']['language']=[v for v in d['vms']['language'] if v['name']!='vde-displaytest']; open(p,'w').write(json.dumps(d,indent=2))"`
