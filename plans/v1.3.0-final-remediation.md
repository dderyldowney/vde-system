# 1.3.0 Hardening Remediation Plan

## Objective
Remediate critical and high-severity security risks identified during the final 1.3.0 audit before cutting the Sovereign Evolution release tag.

## Risks to Remediate
1.  **[CRITICAL] Integer Overflow in `bytes`**: The Rust spoke contains a vulnerable dependency (`bytes@1.11.0`) in `projects/rust/rust-docker/Cargo.lock`.
2.  **[HIGH] Hardcoded Default Password**: `scripts/setup/postgres-init.zsh` falls back to a hardcoded `vde_pass` if no environment variable is provided.

## Implementation Steps
1.  **Remediate `bytes` Vulnerability**:
    *   Navigate to `projects/rust/rust-docker/`.
    *   Execute `cargo update bytes` to bump to version 1.11.1 (or latest).
    *   Verify the `Cargo.lock` is updated and the vulnerability is purged.
2.  **Harden PostgreSQL Initialization**:
    *   Update `scripts/setup/postgres-init.zsh` to REQUIRE `POSTGRES_DEV_PASSWORD` instead of providing a hardcoded default.
    *   If the variable is missing, the script must fail loudly during the build strike (USP Violation).
3.  **Final Verification**:
    *   Rerun the security audit.
    *   Rerun all BDD tests.

## Certification
Once these remediations are applied and verified GREEN, the 1.3.0 release is cleared for tagging.
