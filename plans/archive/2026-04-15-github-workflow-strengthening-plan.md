# Implementation Plan: Strengthening the Chronicle (GitHub Workflow)

## Objective
To strictly codify the "Four Pillars of the Chronicle" into the VDE's operating manuals (`GEMINI.md`, `AGENTS.md`, and `VDE_PROTOCOL.md`) to enforce best practices for GitHub Issues and Pull Requests.

## Background & Motivation
The current workflow mandates the use of Issues (The Signet) and Pull Requests (The Chronicle) but lacks strict enforcement mechanisms for scope containment, explicit linking, automated review prerequisites, and empirical evidence in the PR body. Adopting these best practices prevents scope creep, ensures traceability, and guarantees that only empirically proven code reaches the Anvil (`develop`).

## The Four Pillars
1. **The Law of the Focused Strike:** PRs must remain small and scoped strictly to the initiating Issue. Scope creep requires a new Issue.
2. **The Unbreakable Link:** PRs must use exact auto-closing keywords (e.g., `Closes #N`) to bind to the Issue.
3. **The Dual-Gate Review:** The Orchestrator must invoke the `code-reviewer` agent to validate the PR before presenting it to the User (Clan Leader) for final approval.
4. **The Evidence Mandate:** The PR description must contain the literal terminal output of the empirical tests proving the Heartbeat is green.

## Implementation Steps

### 1. Update `GEMINI.md`
- **Section P (The Sovereign Branching Law):** Inject "The Law of the Focused Strike" and "The Unbreakable Link". Explicitly forbid scope creep and mandate auto-closing keywords.
- **Section R (The Clan Leader Authority):** Inject "The Dual-Gate Review" and "The Evidence Mandate". Require the `code-reviewer` sub-agent execution before the Pre-Merge Halt and require test output in the PR body.

### 2. Update `AGENTS.md`
- **Phase 0 (Mission Ignition):** Add a strict constraint against scope creep. New findings must spawn new Issues.
- **Phase 4 (Review - Dual Approval):** Clarify that the Orchestrator MUST dispatch the `code-reviewer` agent, and only after it passes, seek User approval.
- **Phase 5 (Finalization):** Enforce that the `gh pr create` command (or the resulting PR body) MUST include the exact closing keyword and the literal terminal output of the tests.

### 3. Update `VDE_PROTOCOL.md`
- **Section VI (THE LAWS OF THE FORGE - BRANCHING):** Add a new subsection `6. The Chronicle (Pull Requests)` that summarizes the Four Pillars, serving as the definitive protocol for human and agent contributors alike.

## Verification & Testing
- Read the updated files to ensure the Four Pillars are clearly codified without contradictions.
- The next time a PR is generated by the agent, it must naturally follow this new protocol (this will be tested organically in the next feature strike).
